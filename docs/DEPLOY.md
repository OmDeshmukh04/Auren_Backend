# Deploying the API (Render + Supabase)

## How releases flow

```
feature branch ──PR──▶ main ──GitHub Actions (typecheck, tests, build)──▶ deploy ──▶ Render
```

- Work happens on branches and merges into `main` through pull requests. CI runs on every PR.
- When a merge lands on `main` and CI passes, the workflow fast-forwards `deploy` to that commit. Nobody commits to `deploy` directly; if someone does, the workflow stops and asks for that commit to be merged into `main` first.
- Render watches `deploy`. Each build runs `npm ci`, `npm run build`, then applies pending migrations (`npm run db:migrate:deploy`) before the new instance takes traffic.

## One-time setup on Render

1. Render → **New → Blueprint** → pick this repository. Render reads [`render.yaml`](../render.yaml) and creates `auren-api` (web) and `auren-runner-tick` (cron, every minute).
2. Fill in the values it asks for (below). `AUTH_SECRET`, `SIGNING_SECRET` and `CRON_SECRET` are generated by Render.
3. After the first deploy, copy the API URL (e.g. `https://auren-api.onrender.com`) into `API_ORIGIN` on the cron job, and into `AUREN_API_ORIGIN` on the Vercel frontend.
4. Create the first owner once, from a trusted machine with the production `DATABASE_URL` in a local `.env`: `npm run owner:create -- --email … --name …`.

### Values to enter

| Key | Value |
| --- | --- |
| `DATABASE_URL` | Supabase **session pooler**, port **5432**: `postgresql://postgres.<project-ref>:<password>@aws-0-us-east-1.pooler.supabase.com:5432/postgres`. URL-encode special characters in the password (`@` → `%40`). Don't use the transaction pooler (6543): migrations hold a session advisory lock. |
| `API_PUBLIC_URL` | The Vercel site origin, e.g. `https://auren.vercel.app` (the frontend proxies `/api/*` here, so cookies stay first-party) |
| `PUBLIC_SITE_URL` | Same Vercel origin |
| `STAFF_APP_URL` | `<Vercel origin>/studio` |
| `APP_ORIGINS` | Comma-separated exact origins, e.g. `https://auren.vercel.app,https://www.aurenhouseholds.com` |
| `EMAIL_FROM` | A sender on a domain verified in Resend |
| `RESEND_API_KEY`, `RESEND_WEBHOOK_SECRET` | From Resend. Webhook URL: `<Render API URL>/api/v1/webhooks/resend` |
| `S3_*`, `PUBLIC_MEDIA_BASE_URL` | Cloudflare R2 (or another S3-compatible store). For Supabase Storage use `S3_ENDPOINT=https://<project-ref>.supabase.co/storage/v1/s3` and change `S3_REGION` to the project region. |

Production refuses to start without Resend, S3 storage, `CRON_SECRET` and `APP_ORIGINS` (see `src/config.ts`). `SCANNER_PROVIDER=none` keeps uploads quarantined until a ClamAV daemon is configured. See [RUNBOOK.md](RUNBOOK.md) for monitoring, backups and the owner decisions before launch.

### Database TLS

Supabase certificates chain to Supabase's own root CA, which Node does not trust by default. The CA is committed at `certs/supabase-root-2021-ca.crt` (valid to 2031; also downloadable from Supabase → Database settings → SSL) and loaded through `NODE_EXTRA_CA_CERTS`, so connections stay verified.
